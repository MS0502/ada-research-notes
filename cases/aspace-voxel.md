# 기억을 자동으로 꺼내 주면 복셀 게임이 더 잘 만들어질까

2026년 10월 20일, 같은 에이전트에게 1인칭 3D 복셀 게임을 만들게 하고 A스페이스를 켜고 끈 결과를 비교했습니다. A스페이스는 작업 중 쌓인 사실과 결과 중 현재 단계에 관련 있는 항목을 가져오는 기능입니다.

모델과 채점기 버전을 고정하고 끔 → 켬 → 켬 → 끔 순으로 돌렸습니다. 매번 빈 작업 폴더와 새 기억에서 시작했고, 사전 분석을 포함한 상한은 900초였습니다. 켬·끔 각각 두 번인 탐색 실험입니다.

## 첫 배치가 비교에서 빠진 이유

첫 배치에서 켬 조건 두 실행이 사전 분석 도중 HTTP 429로 끝났습니다. 과제 파일이 생성되기 전이었고, 사전 분석기가 서버 오류를 응답 해석 오류로 기록하고 있었습니다. 서버 장애를 별도 상태로 남기도록 바꾼 뒤 다시 네 번을 실행했습니다. 첫 배치의 429 두 건은 비교 점수에서 제외했습니다. [두 배치의 표](../data/aspace/voxel-runs.csv)

## 재실행에서 본 것

| 조건 | 채점 결과 두 건 | 평균 실행 시간 | 요청에 기록된 평균 토큰 |
| --- | --- | ---: | ---: |
| 끔 | 8/17, 12/17 | 49.1초 | 101,102 |
| 켬 | 13/17, 15/17 | 51.2초 | 132,041 |

토큰은 입력과 출력을 합한 값이며 이전 대화의 재전송도 포함합니다. 켬 조건에서 자동 인출은 총 22회였고, 모델이 기억 항목을 직접 추가하거나 갱신한 기록은 0회였습니다.

채점 항목 수는 켬 조건에서 더 높았습니다. 화면과 코드를 따로 확인했을 때, 네 결과 중 1인칭 3D 게임의 핵심 조건을 갖춘 결과는 없었습니다. 최고 점수에서도 블록 설치·제거가 채점기 버전에 따라 실패로 잡혔습니다. 이 실험은 자동 인출이 작동한 기록과 비용 차이를 보여 주며, 게임 완성도나 장기 기억의 효과까지 가르기에는 표본이 부족합니다.
