# 1M 컨텍스트를 시험하고 262K로 돌아온 이유

2026년 11월 초, RTX 3060 12GB와 RAM 64GB가 있는 개인 PC에서 Q2_0 로컬 모델이 큰 문맥에서도 개발 작업에 쓸 속도를 내는지 확인했습니다. 문맥 크기, KV 캐시 형식, 엔진 버전, 가중치를 읽는 경로를 함께 기록했습니다.

짧은 생성·니들·비전 점검 스크립트의 기록과 Opus의 실험 정리에서 수치를 확인했습니다. 아래는 엔진 점검 결과이며 Ada 작업 하네스에서 과제를 완주하는 비교는 따로 수행하지 않았습니다.

## 어디에서 막혔나

새 엔진에서 1M 컨텍스트의 KV 캐시는 int8에서 12.38 GiB, k8v4에서 9.56 GiB의 RAM을 썼습니다. k8v4에서도 전문가 가중치를 RAM에 전부 올리려면 0.12 GiB가 더 필요했습니다. 엔진은 그 가중치를 디스크에서 직접 읽는 경로로 바꿨습니다.

| 짧은 생성 점검 | 컨텍스트와 KV | 생성 속도 |
| --- | --- | ---: |
| 새 엔진 0.1.57 | 262,144, int8 | 70.9 tok/s |
| 새 엔진 0.1.57 | 262,144, k8v4 | 62.8 tok/s |
| 새 엔진 0.1.57 | 약 1M, int8·k8v4 | 약 12.5–13.2 tok/s |
| 별도의 이전 엔진 점검 | 약 1M, int8 | 49.4 tok/s |

70.9 tok/s는 입력 약 29토큰에서 일반 생성 256토큰을 요청한 짧은 점검에서 서버가 보고한 생성 속도입니다. 위 행 사이에는 엔진·캐시·문맥·가중치 적재 경로 차이가 있습니다. 전체 작업에서 문맥 크기만 바꿨을 때의 속도 차이는 이 수치로 계산할 수 없습니다.

실험 후 개발 런은 262K와 int8 KV 조합으로 되돌렸습니다. 해당 조합에서 200K 위치에 둔 문자열을 찾는 검사와 두 색을 식별하는 이미지 검사도 통과했습니다. 200K 검사는 문맥에 넣은 특정 문자열을 찾을 수 있는지 확인했습니다.
