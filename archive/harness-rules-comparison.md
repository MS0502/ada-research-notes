# 같은 과제를 네 가지 에이전트 실행 구성으로 비교하기

이 실험은 같은 시뮬레이션 최적화 과제에서 에이전트 실행 구성을 바꾸면 통과 수가 어떻게 달라지는지 봤습니다. 두 배치 모두 과제 식별자는 `edge2`, 실행 예산은 시행당 1,800초였습니다. 각 행의 분모는 해당 구성의 시행 수입니다.

| 실행 구성 | 첫 배치 m9 | 후속 배치 m10 |
| --- | ---: | ---: |
| 짧은 규칙 (`slim`) | 4/8 | 10/15 |
| 최소 구성 (`bare`) | 2/8 | 6/15 |
| 기존 구성 (`s80`) | 1/8 | 3/15 |
| 규칙이 많은 구성 (`heavy`) | 0/8 | 7/15 |

## 첫 표에서 놓치기 쉬웠던 점

첫 배치에서 `heavy` 조건의 세 시행에 HTTP 404가 한 번씩 기록됐고, 해당 요청은 재시도됐습니다. 위 표는 각 배치에 기록된 최종 통과 여부를 셌습니다. 404가 개별 판정에 얼마나 기여했는지는 여기서 분리해 측정하지 않았습니다.

`slim`은 두 배치에서 가장 많이 통과했습니다. `heavy`의 첫 배치 0/8은 후속에서 반복되지 않았습니다. 두 배치의 결과를 함께 보고해야 같은 조건의 결과가 얼마나 달라질 수 있는지 보입니다. 한 과제에서 관측한 순위이며, 다른 과제에서 규칙을 줄였을 때의 효과는 별도 실험이 필요합니다.

## 이후 비교에서 같이 기록할 항목

조건별 총 시행 수와 통과 수, 실행 예산, API 오류가 발생한 시행, 재시도와 최종 판정입니다. 별도 추론 속도 측정은 해당 측정의 모델·문맥·KV 조건과 함께 독립된 기록에 둡니다.
